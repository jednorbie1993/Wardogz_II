TITLE:
Player Walking Animation System - Updated JWALK System

===========================================================
OVERVIEW
===========================================================

This document records the player walking animation system for Jamber.

The walking animation originally used fewer frames, but the player walk
sprites were later replaced and expanded into the current JWALK sequence.

Current walking animation:

JWALK1
JWALK2
JWALK3
JWALK4
JWALK5
JWALK6
JWALK7
JWALK8
JWALK9
JWALK10
JWALK11

===========================================================
1. WALKING STATE
===========================================================

The player enters the walking animation while movement input is active.

When the player is not moving and is not attacking, the normal idle or
battle-idle animation can be shown instead.

The walking system uses:

player->isWalking
player->walkTimer
player->walkFrame
player->walkFrameTime

===========================================================
2. WALK TIMER
===========================================================

While the player is walking:

player->walkTimer += deltaTime;

When the timer reaches the required frame duration, the walk frame is
advanced and the timer is reset.

===========================================================
3. CURRENT JWALK FRAME TIMING
===========================================================

The current JWALK animation is split into two timing groups.

JWALK1 - JWALK5
    Fast starting / buildup frames.

Reference frame time:

0.06f seconds

JWALK6 - JWALK11
    Normal walking cycle speed.

Reference logic:

if (player->walkFrame <= 4)
{
    currentWalkFrameTime = 0.06f;
}
else
{
    currentWalkFrameTime = player->walkFrameTime;
}

This creates a quicker movement buildup at the start of the walking
animation before the normal walk cycle continues.

===========================================================
4. WALK FRAME RANGE
===========================================================

The current player walk animation uses 11 frames.

Frame index reference:

0  = JWALK1
1  = JWALK2
2  = JWALK3
3  = JWALK4
4  = JWALK5
5  = JWALK6
6  = JWALK7
7  = JWALK8
8  = JWALK9
9  = JWALK10
10 = JWALK11

The frame index must stay inside the valid walking texture range.

===========================================================
5. CURRENT PLAYER WALK IMAGE DIRECTION
===========================================================

Jamber's current walking sprites follow the same character design used
throughout the player image system.

Visual rules:

- white dog head
- black tactical vest
- muscular brown arms with white patches
- olive cargo pants
- black combat boots
- retro pixel-art fighting-game style
- classic arcade / KOF-like texture
- not chubby
- slightly larger head than older versions
- slightly darker overall shading

===========================================================
6. WALK FRAME FOOT PLACEMENT
===========================================================

Each walking frame must show a natural alternating leg position.

Recent sprite correction:

Body facing right.

Corrected pose example:

- left foot forward
- right foot behind

Other frames should alternate the legs naturally so the animation looks
like a real walk cycle instead of repeating the same stance.

Changing foot placement in a PNG is an image/sprite correction and does
not normally require changing movement code.

===========================================================
7. FACING DIRECTION
===========================================================

The player can face left or right depending on horizontal movement.

The sprite drawing system may mirror the current walking texture when
the player faces the opposite direction.

The walk animation itself should keep one consistent base-facing
direction in the source PNG files.

===========================================================
8. DEPTH SCALING DURING WALKING
===========================================================

Walking sprites continue to use the player depth/perspective scaling
system.

The character appears:

- smaller toward the top/back of the stage
- larger toward the bottom/front of the stage

The walking animation must remain anchored at the feet so changing
animation frames does not make the character jump vertically.

===========================================================
9. CURRENT TEXTURE DIMENSIONS
===========================================================

DrawPlayer should use the dimensions of the currently active texture.

This is important because newer JWALK images may have different canvas
dimensions from older sprites.

Do not hard-code the old PNG dimensions when drawing the current walk
frames.

===========================================================
10. WALK IMAGE REPLACEMENT RULE
===========================================================

When replacing a JWALK image:

1. Keep the full body visible.
2. Do not crop ears, head, hands, or boots.
3. Keep feet near the same bottom anchor.
4. Keep the same Jamber design.
5. Keep body proportions consistent.
6. Keep natural alternating leg positions.
7. Preserve the intended facing direction.
8. Keep the retro pixel-art texture.
9. Test the new frame in-game.
10. Do not change movement physics only because the PNG changed.

===========================================================
11. CURRENT STATUS
===========================================================

DONE / IMPLEMENTED:

- Walk frame animation
- 11-frame JWALK sequence
- JWALK1-JWALK5 fast startup timing
- JWALK6-JWALK11 normal walk timing
