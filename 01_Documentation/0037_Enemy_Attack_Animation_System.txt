============================================================
PURPOSE
============================================================

This update adds dedicated attack animations to the Stage 1 Punk enemy.

Before 0037, Punk already had:

- Idle animation
- Walking animation
- Chase behavior
- Attack range / stop behavior
- Basic enemy attack damage
- Enemy attack hitbox

However, the enemy attack did not yet have dedicated sprite animation
for different moves.

0037 adds two Punk attack moves:

1. Punch
2. Elbow

============================================================
ATTACK MOVE ENUM
============================================================

The enemy system uses:

EnemyAttackMove


Current values:

ENEMY_ATTACK_PUNCH
ENEMY_ATTACK_ELBOW


This allows the shared enemy system to know which attack animation
and attack settings are currently active.


============================================================
ATTACK ANIMATION DATA
============================================================

The Enemy structure stores:

Texture2D punchTextures[MAX_ENEMY_ATTACK_FRAMES];
Texture2D elbowTextures[MAX_ENEMY_ATTACK_FRAMES];

int punchFrameCount;
int elbowFrameCount;

int attackFrame;
float attackFrameTimer;
float attackFrameTime;

EnemyAttackMove currentAttackMove;
EnemyAttackMove nextAttackMove;


Purpose:

currentAttackMove
=
The attack currently being performed.


nextAttackMove
=
The attack Punk should use next.


attackFrame
=
Current attack animation frame.


attackFrameTimer
=
Counts time between attack frames.


attackFrameTime
=
Controls attack animation speed.


============================================================
ATTACK ANIMATION SPEED
============================================================

The Punk attack animation speed is configured in:

src/enemy/stage_1/punk.c


Example:

enemy.attackFrameTime = 0.11f;


Smaller value:

Faster attack animation.


Larger value:

Slower attack animation.


Examples:

0.08f
=
Fast


0.11f
=
Current / medium


0.15f
=
Slower


============================================================
PUNCH / ELBOW ALTERNATION
============================================================

Punk alternates between the two moves.

Current intended order:

PUNCH
->
ELBOW
->
PUNCH
->
ELBOW
->
repeat


Important fix:

The next move should change only AFTER the current attack finishes.

This prevents the move order from being skipped when Punk is interrupted
or hit during an attack.


Example:

Punk begins Punch.

If Punk is hit before Punch finishes:

- Current attack is cancelled.
- The next attack should still remain Punch.

If Punch finishes normally:

- Next move becomes Elbow.


============================================================
ATTACK INTERRUPTION
============================================================

If Punk is hit while attacking:

- Attack animation is cancelled.
- Attack timer resets.
- Attack frame resets.
- Hit reaction / knockback takes priority.

This prevents the attack animation from continuing while Punk is already
being knocked backward.


============================================================
ATTACK DRAW PRIORITY
============================================================

The drawing system uses attack animation before walking or idle.

Priority:

ATTACK
->
WALK
->
IDLE


When Punk is attacking:

Punch:
enemy.punchTextures[enemy.attackFrame]

or:

Elbow:
enemy.elbowTextures[enemy.attackFrame]


The existing facing / mirror system is preserved.


============================================================
SPRITE FACING
============================================================

The original Punk sprites face RIGHT.

When Punk faces LEFT, raylib mirrors the active texture.

This means separate LEFT attack sprite files are not required.


============================================================
ATTACK TEXTURE CLEANUP
============================================================

UnloadEnemy() also unloads:

- Punch textures
- Elbow textures


Punch loop:

for (int i = 0; i < enemy->punchFrameCount; i++)
{
    UnloadTexture(enemy->punchTextures[i]);
}


Elbow loop:

for (int i = 0; i < enemy->elbowFrameCount; i++)
{
    UnloadTexture(enemy->elbowTextures[i]);
}


============================================================
PUNCH IMAGE GLITCH FIX
============================================================

During 0037 testing, one Punch sprite appeared to show repeated or extra
body parts.

Important:

A 1024 x 1024 PNG can still contain unwanted pixels or leftover parts
from another animation frame.

raylib draws the entire texture canvas.

Therefore:

- Extra feet
- Extra arms
- Leftover sprite pieces
- Stray pixels

must be removed from the PNG itself in Photopea.


This is an image / sprite problem, not necessarily an animation-code
problem.
