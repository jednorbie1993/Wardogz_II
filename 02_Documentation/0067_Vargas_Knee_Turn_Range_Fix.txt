0067 - KNEE ATTACK TURN RANGE FIX
============================================================

Problem:

Vargas stopped at the intended Knee distance but would not start Knee until
the player moved much closer, around 190-200 pixels.

Root cause:

ResolveEnemyAttackTurnTiming() inside src/enemy/enemy.c still selected only
the Punch or Elbow/Kick range. Knee therefore used:

    enemy.punchAttackRange = 190.0f;

even though:

    enemy.bossKneeAttackRange = 405.0f;

Fix:

The requiredAttackRange selection inside ResolveEnemyAttackTurnTiming() was
changed to include ENEMY_ATTACK_BOSS_KNEE:

    float requiredAttackRange;

    switch (enemy->nextAttackMove)
    {
        case ENEMY_ATTACK_ELBOW:
            requiredAttackRange = enemy->elbowAttackRange;
            break;

        case ENEMY_ATTACK_BOSS_KNEE:
            requiredAttackRange = enemy->bossKneeAttackRange;
            break;

        default:
            requiredAttackRange = enemy->punchAttackRange;
            break;
    }

The Knee distance must be recognized in three different systems:

1. src/enemy/enemy_attack.c
   - Confirms the attack can start within bossKneeAttackRange.

2. src/enemy/enemy_move.c
   - Stops Vargas at bossKneeStopDistance.

3. src/enemy/enemy.c
   - Allows the shared attack-turn controller to grant the Knee attack using
     bossKneeAttackRange instead of punchAttackRange.

Without the third update, Knee continues waiting for the old Punch range even
when the Knee AttackRange and StopDistance values are correct.
